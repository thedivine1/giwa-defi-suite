How to add on-chain actions

Extensibility design for v2 integrations. We propose two paths for reading additional signals.

Path A: Off-chain Indexer

An indexer watches protocol events and the owner calls setManualScore(wallet, score) or submits a signed score. Simple to implement, but trust-centralized to the backend infrastructure.

Path B: On-chain Registry (Recommended)

A pluggable signal registry where a recordSignal(signalId, wallet, value) function is gated to a whitelist of signalReporter contracts (each protocol registers itself). Each signalId carries a weight and a decay half-life set by governance. The composite score becomes:

score = min(1000, baseAttestationScore + Σ decayed_signal_contributions)
Worked Example: A wallet that swaps 5× and provides LP accrues +100 of "activity trust". This decays over 90 days if they go idle. Thus, the score rewards recent, real usage and resists one-time farming.

Trust Assumption: Reporter contracts must be honest. This is mitigated via the whitelist, per-signal caps, and relying heavily on the base attestation floor.

Fee & monetization model

Revenue generation for DojangScore infrastructure.
  • Free On-chain View: In v1, the on-chain score() is a free view call — there is no per-call charge to smart contracts querying trust.
  • Premium API: Revenue comes primarily from an off-chain REST/GraphQL API offering score history, batch scoring, and risk flags at stated tiers (e.g., free 1k calls/mo, $500/mo for 100k calls, $2k/mo for 1M calls, and enterprise custom plans).
  • Airdrop & Sybil-gating: A flat fee per token distribution for protocols utilizing DojangScore to filter Sybils out of airdrops.
  • Paid Wrapper (Roadmap): An optional on-chain scoreFor(wallet) state-modifying call that requires a tiny fee forwarded to the treasury, acting as an on-chain receipt for protocols that demand it.

Security & trust assumptions

How we minimize trust requirements while delivering robust identity attestation.
  • The Attester: Upbit Korea (id keccak256("dojang.dojangattesterids.upbitkorea")) is the trusted root. If its key is compromised, attestations and scores are inaccurate.
  • Mitigations: 90-day attestation expiry requires periodic refresh, limiting the window of a compromised signal. A multi-attester quorum is on the roadmap.
  • Upstream Trust: The EAS predeploy and DojangScroll contracts are assumed to be secure and operational.
  • Privacy: No PII is ever placed on-chain. Only signed booleans, tiers, and cryptographic identifiers are stored.
  • Dashboard Philosophy: The UI employs a clamp approach — it refuses to render a value it cannot fully reconcile, failing safely rather than displaying unverified trust.
Trust is the primitive that unlocks capital efficiency.
