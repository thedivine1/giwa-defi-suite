§ 1

Why ERC-4626

The Ethereum tokenized-vault standard. Any wallet, aggregator, or yield router integrates with zero custom code.
Interface guarantees

ERC-4626 defines a complete bidirectional interface: deposit, withdraw, mint, redeem plus the accounting helpers convertToAssets, convertToShares, totalAssets, totalSupply. Any party that speaks ERC-4626 reads WonVault correctly without a custom adapter.

Our implementation extends OpenZeppelin v5's ERC4626, meaning the share-minting, asset-transfer, and accounting invariants ship from a thoroughly-audited library base — not hand-rolled math. The share-price mechanism is the yield mechanism: see §3.

Decimal offset override: we set _decimalsOffset() = 18, which inflates the virtual share supply by 1 × 10¹⁸ and adds a corresponding virtual asset unit. This neutralizes the first-depositor inflation attack (the exact bug that produced our 1.09 × 10²¹ share price on an earlier testnet build). The full security argument is in §5.

Management fee: 1.00%/yr accrued continuously into the share price via a virtual assets increase per block — no discrete event, no depositor action required.

Performance fee: 15% of realized yield taken at each harvest and minted as shares to treasury (dilutive-by-design, per Yearn/Morpho standard).

perfFee_shares = floor(realizedYield_assets × 1500 / 10000)
// minted to treasury → dilutes existing holders by design
// this is the performance carry; entry+management fees are split

Operator / protocol split policy: Performance fee is operator carry. Entry and management fees are shared with the GIWA ecosystem (proposed 50/50) so the protocol has a recurring revenue stake proportional to TVL activity — not a one-time listing fee.
§ 5 · most important

Security & trust model

Read this section before auditing, forking, or deploying to mainnet.

⚠ Simulation yield — testnet only

On testnet, the "yield source" is MockERC20's open mint(vault, amount). This is a simulation so judges can watch the accrual engine in a live demo. On mainnet, this open mint MUST be removed entirely. Value may enter the vault only through a role-gated harvest() called by a whitelisted strategy contract that has actually earned external yield (e.g. from a Dunamu-backed KRW yield source). No exceptions. The testnet build is not a mainnet reference.

Inflation / first-depositor / donation attack

Without the decimal offset, an attacker can deposit 1 wei to an empty vault, then donate a large amount directly to the vault's asset balance. This inflates totalAssets / totalSupply — so the next depositor's shares round to zero (the pathology that produced our 1.09 × 10²¹ share price in an earlier testnet build — we caught and patched it before any real money was at risk).

Fix: _decimalsOffset() = 18 makes the virtual supply 10¹⁸ × larger. An attacker must donate 10¹⁸ × the "attack capital" to move the price by 1 wei of shares — making the attack economically infeasible. This is the same defense used by Morpho, Euler v2, and OZ's own documentation.

// protected invariant with offset
virtualSupply = totalSupply + 1018
virtualAssets = totalAssets + 1
sharePrice = virtualAssets / virtualSupply

// attacker needs ≥ 10^18 TKRW donation to inflate by 1 wei
// ∴ attack cost >> any rational yield extraction

Oracle discipline

Any price the strategy trusts for rebalancing or yield calculation must be a TWAP, Chainlink feed, or Pyth pull oracle. Spot DEX quotes are manipulable within a single block — using them as an input to a harvest function is a known vector for flash-loan-driven bad debt. This is a mainnet checklist item, not a testnet constraint.

Roles & emergency brake

Access is managed via OpenZeppelin AccessControl with four roles: governor (governance), curator (parameter tuning), keeper (harvest calls), guardian (emergency). The guardian can pause or quarantine a strategy without a governance delay — providing a fast response path to a detected exploit. Owner and treasury keys are held in a Safe multisig.

The dashboard as a control surface

The live app clamps the displayed share price to a sanity band (0.5 – 5.0) and shows — / "degraded" when the price falls outside it. This is the same check that surfaced the 1e21 price before any user saw it. The UI is defense-in-depth: if the contract state is wrong, the dashboard renders wrong, not silently normal. This is not decoration.

§ 6

Trust assumptions summary

  • DojangScore (fee tier): A wrong DojangScore sets the wrong entry fee tier — a user might pay 2.00% instead of 0.50%, or vice versa. This is a pricing error, not a principal-safety error. The depositor's net TKRW and share entitlement are correct; only the fee amount changes.
  • Upbit Korea attester: Transitively trusted through DojangScore. A compromised attester key inflates or deflates trust scores, mis-pricing fees. Mitigated by 90-day attestation expiry; multi-attester quorum on roadmap.
  • Asset counterparty (TKRW): Testnet TKRW is a mock with open faucet() — no economic value. On mainnet the asset is intended to be the Dunamu/Naver KRW-backed stablecoin, which carries its own issuer counterparty risk and regulatory exposure. A KRW stablecoin depeg directly reduces every depositor's real-world value regardless of share-price correctness.
  • ERC-4626 + OpenZeppelin v5: Assumed correct per the library's audit history. Any undiscovered critical vulnerability in OZ v5 is a direct risk to vault principal. Mitigation: a WonVault-specific audit pre-mainnet.
